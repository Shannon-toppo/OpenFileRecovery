# カービングに追加するファイル形式の候補

`ofr carve` に足す形式の候補を、実装難易度と一緒にまとめた一覧。
USB メモリと SD カードからの復元でよく出会う順に並べている。

難易度を決めるのは、たいてい「ファイルの終わりをどう判定するか」になる。
ヘッダにサイズが書いてある形式は簡単で、終端マーカーもサイズ情報もない形式は難しい。

## 形式を 1 つ足すときの共通作業

既存のバリデータは 1 本 64〜206 行。どの形式でも次の箇所を触る。

- `crates/ofr-carve/src/format.rs`: `FileFormat` の変種、`all()`、`from_name()`、`category()`
- `crates/ofr-carve/src/signature.rs`: シグネチャ表に 1 行(既存のマジックに相乗りするなら `formats` に追加)
- `app/src/screens/Setup.svelte`: GUI の形式一覧 `allFormats`
- `crates/ofr-core/src/session.rs`: プレビュー用の `mime_for`
- `crates/ofr-carve/tests/support/mod.rs` と `tests/carving.rs`: テスト用の合成ファイルと検証
- `README.md`: `ofr carve` の対応形式

## 易: 既存のバリデータに数行足せば済むもの

| 形式 | 主な用途 | やること | 状態 |
|---|---|---|---|
| WebP | スマホやブラウザの保存画像 | RIFF のフォーム種別 `WEBP` を `riff.rs` に追加。終端は RIFF のサイズで確定する | 実装済み |
| AVIF | 新しめのスマホ写真 | `isobmff.rs` の `brand_to_format` に `avif`/`avis` を追加 | 実装済み |
| CR3 (Canon RAW) | Canon のミラーレス、新しめの一眼 | ISO-BMFF のブランド `crx ` を追加 | 実装済み |
| M4A を音声として分離 | ボイスメモ、iTunes | それまで Mp4 扱いで「動画」フォルダに入っていた。`FileFormat::M4a` を分ける | 実装済み |
| ODT/ODS/EPUB/APK/JAR | 文書、電子書籍 | `zip.rs` の判別表に `mimetype` や `AndroidManifest.xml` などの手がかりを追加 | 未着手 |
| 7z | 書庫 | 開始ヘッダに次ヘッダのオフセットとサイズが入っていて、終端が確定する | 未着手 |
| AMR | ガラケーや IC レコーダーの録音 | マジック `#!AMR\n` のあとに固定長フレームが続き、歩くのは簡単 | 未着手 |
| SQLite | アプリのデータ | ヘッダのページサイズ × ページ数が全長になる | 未着手 |

## 中: 新しいバリデータを 1 本書くもの

| 形式 | 主な用途 | 難しいところ |
|---|---|---|
| TIFF 系 RAW (CR2/NEF/ARW/DNG/ORF/RW2/PEF) と TIFF | 一眼レフの SD カード | 総サイズがどこにも書かれていない。IFD とサブ IFD をたどり、ストリップやタイル、埋め込み JPEG の最大終端オフセットを求める。`II*\0` だけだと機種が分からないので、Make タグや独自マジック (ORF の `IIRO`、RW2 の `IIU\0`) で拡張子を決める。メタデータは `exif.rs` の `read_tiff` を使い回せるが、終端を求める IFD 走査は新しく書く必要がある。手間はかかるが、カメラ用途では一番効く |
| RAF (Fujifilm) | 富士フイルムのカメラ | ヘッダに各ブロックのオフセットと長さがあり、TIFF 系より楽 |
| AAC (ADTS) | 録音、配信の保存 | フレーム列を歩く処理は `mp3.rs` と同じ。同期語が `FFF1`/`FFF9` の 2 バイトしかなく、誤検出の抑え方も MP3 と同じ工夫が要る |
| Ogg (Vorbis/Opus) | 音声 | `OggS` ページが連続し、各ページに CRC がある。最終ページの EOS フラグで終端が確定する |
| FLAC | ハイレゾ音源 | メタデータブロックは歩けるが、本体のフレームに長さがない。フレームヘッダの CRC8 を確かめながら、フレームが続かなくなるまで進む |
| WMV/WMA (ASF) | 古い Windows 系の機器 | GUID ヘッダの File Properties Object にファイルサイズがある。マジックが 16 バイトあり誤検出も少ない |
| BMP | スクリーンショット、古い機器 | ヘッダにサイズはあるが、マジック `BM` が 2 バイトしかない。DIB ヘッダの値を細かく検証して誤検出を絞る |
| PSD | Photoshop | `8BPS` のあとに長さ付きのセクションが 4 つ並ぶ。最後の画像データは圧縮方式から長さを計算する |
| RAR (4/5) | 書庫 | ブロック列を歩く。RAR4 と RAR5 で構造が違うので実装は 2 本になる |
| 旧 Office (doc/xls/ppt) | 古い文書 | OLE2 (`D0 CF 11 E0`)。FAT セクタ数から上限は出せるが、末尾が正確に決まらないことが多く「推定」での出力が増える |

## 難: 走査の仕組みから手を入れるもの

| 形式 | 主な用途 | 難しいところ |
|---|---|---|
| AVCHD / MPEG-TS (.mts/.m2ts) | Sony や Panasonic のビデオカメラ | ファイル先頭を示すマジックがない。同期バイト `0x47` が 188 バイト (m2ts は 192 バイト) ごとに並ぶことで見分けるしかなく、今の「マジック検索 → probe」の 2 段構えに乗らない。録画は断片化しやすく、境界も曖昧。需要は大きい |
| MKV / WebM | 画面録画、ダウンロード動画 | EBML ヘッダは見つけやすい。録画中のファイルは Segment のサイズが「不明」のことがあり、Cluster を歩いて終端を探すことになる |
| MPEG-PS (.mpg/.vob) | 古いビデオカメラや DVD | `00 00 01 BA` のパックが続くだけで全長の情報がない。終端は次のシグネチャか上限で切るしかない |
| gzip / tar.gz | 書庫 | 終端を知るには deflate ストリームを最後まで展開する必要があり、展開器への依存が増える |
| テキスト系 (txt/csv/rtf/html) | メモ | マジックがない。文字種の統計で判定するしかなく、誤検出との兼ね合いが本質的に難しい |

## 進め方

1. **易の WebP・AVIF・CR3・M4A の分離** (実装済み)。どれも数十行で、スマホやカメラのカードでそのまま効く。
2. **TIFF 系 RAW**。一眼レフのカードを想定するなら一番価値がある。IFD をたどる処理を 1 本書けば、CR2、NEF、ARW、DNG にまとめて対応できる。
3. **AVCHD (MPEG-TS)**。ビデオカメラを対象にするなら避けて通れない。走査器の設計変更が要るので、別フェーズとして計画する。

修復 (`ofr repair`) を広げるなら HEIC とカメラ RAW が候補になる。どちらもカービングより大幅に重いので、この一覧には含めていない。

## 実装済みの分の補足

- WebP は単純形式 (`VP8 `、`VP8L`) と拡張形式 (`VP8X`) の両方で寸法を拾う。
- AVIF は主ブランドが HEIF 共通の `mif1`/`msf1` でも、互換ブランドに `avif` があれば AVIF と判定する。
  これまで `mif1` 主ブランドのファイルは無条件に HEIC になっていた。
- M4A は `M4A ` と `M4B ` (オーディオブック) のブランドを拾い、出力先は「音声」フォルダになる。
  `--formats m4a` の指定先も Mp4 から M4a に変わった。
- CR3 は ISO-BMFF のボックス列をそのまま歩くので、`mvhd` の撮影日時がファイル名に付く。
  寸法と機種名は CMT ボックス内の TIFF にあるが、まだ読んでいない。
